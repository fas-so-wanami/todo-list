## 段階② 複数ユーザー化(ログインで本人を判別する)

ゴール: 1 つのサーバーを複数人で使い、各自が自分のタスクだけを見て操作できる。

### 実装済みの土台(2026-11-13)

- すべての表に `user_id` があり、問い合わせは `user_id` で絞っている。
- タスクを操作するルートは、すべて「本人のタスクか」を確かめている(`main.py` の `OwnedTask`、`tasks.get_owned_task`)。本人の `user_id` はリクエストごとに認証から決める。
- `users.email` と一意索引を追加し、既存DBのユーザー・タスク・日報を変えずに移行する。`TODO_DATA_OWNER_EMAIL` で既存 `user_id=1` の持ち主を明示できる。
- `TODO_AUTH_MODE=local` は従来の固定ユーザー、`dev` はローカルユーザー選択、`entra` はEntra IDのメールヘッダー・許可リストで本人を識別する。実DBの開発切替は `data/local_auth.json` に所有者メールが明示された場合のみ有効。
- リクエストごとの本人IDでタスク、案件、WBS、日報、アーカイブ、各操作を絞り込む。未認証・許可外ユーザーは拒否する。
- 開発モードのユーザー選択、2ユーザー間のタスク・日報分離、Entraヘッダーの許可検査を一時DBテストで確認する。

### Azureで使う前に残っていること

1. **Azure側のEntra IDとEasy Authを設定する**
   - `TODO_AUTH_MODE=entra`、`TODO_ALLOWED_USER_EMAILS`、`TODO_MANAGER_EMAILS`、`TODO_DATA_OWNER_EMAIL`をApp Serviceの設定に登録する。
   - Easy Authを有効にし、アプリが信頼するメールヘッダーを公式仕様と実際のリクエストで確かめる。
   - `TODO_DATA_OWNER_EMAIL`には既存DBの持ち主本人を指定し、そのアドレスを許可リストにも含める。
2. **受け付けるホスト名を設定で変えられるようにする**
   - 今は `127.0.0.1` と `localhost` だけ(`main.py` の `LOCAL_HOSTNAMES`)。Azureのアドレス(`○○.azurewebsites.net`)を許可する設定を追加する。
3. **3秒ごとの自動更新確認を外す**(または間隔を延ばす)
   - `base.html` の `/api/data-version` の定期確認。一時停止中の Copilot 連携のための仕組みで、チームでは不要。
   - 無料プランの通信量の上限に効く(設計方針 7.1 章の実測)。
4. **Azureで2人の分離を確認する**: 許可外ユーザーが入れないこと、メンバー間でタスク・日報が見えないことを実DBのコピーで確認する。
5. **テストを足す**: 2 人のユーザーで、お互いのタスク・日報が見えないこと。

## 段階③ 上司画面

ゴール: 上司役(今は 3 人)が、メンバー全員の「長時間化・期限超過・相談中(理由つき)」を一覧できる。

- 上司役は、環境変数にメールアドレスを列挙して決める(例: `TODO_MANAGER_EMAILS`。設計方針 3 章)。
- 画面は 1 つ追加する(例: `/team`)。上司役以外が開いたら断る。
- 拾うもの(設計方針 4 章):
  - 長時間化: 累計 5 時間以上(`tasks.LONG_RUNNING_MINUTES`、`enrich` の `is_long_running`)
  - 期限超過: `is_overdue`
  - 相談中と理由: `has_open_blocker`、`blocker_note`
- 上司は閲覧だけ。編集は本人だけ。工数の集計や順位付けは作らない(設計方針 5 章)。
- 見た目は今の帳票の形(列見出し付きの表)に合わせ、人ごとにまとめる。色のルールは設計方針 7.4 章。

## 段階④ Azure に載せる(手動)

ゴール: App Service の無料プランで、チームが使える状態にする。

1. **Azure 側の準備**(設計方針 7.1 章の方針)
   - このアプリ用のリソースグループと、**専用の無料プラン(Linux)** を作る。業務支援系のアプリとまとめて管理する。
   - Python のバージョンは手元と同じ 3.11 を選ぶ。
2. **起動のしかた**
   - Azure では `start.bat` と `app/launcher.py` は使わない(手元専用)。
   - 起動コマンドは `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000` の形(**要確認**: App Service の Python の起動コマンドとポート)。
   - データベースの置き場所は、環境変数 `TODO_DB_PATH` で `/home` 以下を指定する(`/home` は再起動しても消えない領域。**要確認**)。
3. **ログイン**: App Service の「認証」で Microsoft(Entra ID)を有効にし、ログインしていない人は入れないようにする。
4. **バックアップ**: `todo.db` を定期的にコピーする手順を決める(App Service のバックアップ機能は無料プランで使えるか **要確認**)。
5. **確かめること**: 載せたあと、2 人でログインして、お互いのタスクが見えないこと。上司役が上司画面を開けること。通信量とCPU時間を、ポータルの「App Service プラン」→「クォータ」で数日見る。
