ToDo・WBS・日報
連携のたたき台

タスクを一度登録し、チームの予定確認から個人の日報提出までつなぐ。これまでの相談内容と、次に進めるための作業をまとめました。

毎日の入力は、軽いまま。既存のToDoを中心に、案件の予定と進捗を共有。新しい作業の入力や、複雑な設定をできるだけ増やしません。

01 / 全体像

記録は一度。見る相手に合わせてつなぐ。

参考のWBSやRedmineの考え方を取り入れつつ、ToDo側で案件・作業・予定を管理します。資料のExcelや参考アプリとの自動連携は、今回の前提にしていません。

01 / 管理者・担当者タスクを登録

管理者が案件の大枠を作り、担当者も必要な作業を追加。

02 / チーム予定と進捗を見る

同じ案件の共有タスクを、担当者をまたいで確認。

03 / 担当者・上司日報を提出

日々の操作から候補を作り、提出後に上司が確認。

現在地：案件管理とローカルWBS（週4週・日7日、状態・予定・名前の絞り込み、今日の位置表示、閲覧専用）は実装済みです。複数人の共有・担当者・権限、上司への日報表示は未実装です。この資料の残りは今後の検討用です。
02 / タスク

案件 → 親 → 子。それ以上は増やさない。

案件の中に親タスクを置き、その下に分担する子タスクを並べます。子の下には孫タスクを作りません。

登録は手軽に

名前だけで追加でき、必要なら担当者・開始予定日・期限なども入力。子タスクの担当者は１人で、追加した人を初期値にする案です。

作業が増えたら

付随する作業は別の子タスクとして追加。共有の子がすべて完了しても親は自動完了せず、人が「親も完了にする」を選びます。

複雑にしないために

  • 期限前の細かな進み具合は信号で判定しない。
  • 色だけに頼らず、状態を文字でも示す。
  • 見た目が複雑なら、一覧表だけにする選択肢を残す。
  • 親の信号や予定・実績の件数の詳しい計算は未決定。
期限を自動で当日に設定したタスクは、翌日も未完了なら期限超過になります。入力を簡単にできる一方、実際の予定と合わない場合は日付の見直しが必要です。
04 / 共有と権限

見せる範囲は、２つだけ

共有

チームと上司に見える。案件タスクは共有を初期値にし、担当者と管理者が更新する方向です。

自分だけ

本人以外には見せない。チームの一覧・ガント・進捗件数に含めず、共有の親の完了条件にも含めません。

共有の親と非共有の子：共有の子がすべて完了すれば親を完了できます。非共有の子は未完了でも本人の作業として残し、親の完了や収納によって見失わないようにします。

日報の「その他」には非共有タスクの記録時間を合算するため、上司には非共有の作業があることが分かります。タスク名・件数は表示しません。

05 / 日付の扱い

空欄でも追加でき、矛盾は残さない

項目・場面たたき台のルール
開始予定日が空欄登録日を自動設定。指定した期限が過去なら、期限日に合わせる。
期限が空欄原則、登録日を自動設定。開始予定日が未来なら、その開始予定日に合わせる。
両方を手入力して矛盾勝手に変更せず、開始予定日が期限以前になるよう確認を出す。
実際の開始日「開始する」を押した日を記録。押す前は未設定。
開始予定日は予定、実際の開始日は実績です。上の自動設定は新しい運用案であり、現在は子タスクの開始日・期限を空欄のまま追加できます。既存の空欄データをどう扱うかは実装前に確認します。
06 / 日報

候補は自動、提出は本人が決める

着手・完了などを更新したタスクをその日の日報候補に入れ、必要なら追加・削除できる案です。更新せずに作業したタスクは、自分で追加する必要があります。

01 / 担当者候補を確認

自動で入った候補を調整し、必要な作業時間を入力。

02 / 担当者日報を提出

提出前の下書きは本人だけが見られる。

提出後の修正

修正中は上司に前回提出分を表示。再提出したら新しい内容に切り替えます。修正中の下書きは見せません。

公開範囲の変更

提出後に共有から「自分だけ」に変更したら、過去の日報でもすぐ名前を隠し、提出済みの時間を「その他」にまとめ直します。

「その他」の内訳や件数は表示しません。集計の対象は日報に記録された時間であり、入力されていない時間を自動推測するものではありません。

07 / 次に作る人へ

実装するなら、この順番で小さく進める

案件管理とローカルWBSの第一段階は実装済みです。複数人の共有や上司向け機能は、環境と未決定事項を確認してから進めます。

  1. 方針と既存データの扱いを決める

    設計方針と次の作業を確認。今の「本人のみ編集」「上司が全タスクを閲覧」「工数集計・レポート出力は後回し」と、今回の案の違いを整理し、合意後に方針を更新する。実データを消さず、既存の期限・開始日が空欄のタスクの移行方法を決める。

  2. 共有・ログイン・権限の土台を作る

    １人固定から本人を識別する形へ。案件・担当者・管理者・共有範囲を扱い、画面だけでなくサーバー側でも他人の非共有データを拒否する。共有先・管理者の決め方は先に確認。

  3. タスクと親子の扱いをつなぐ

    案件の親子・担当者・公開範囲を登録。追加時の日付補完、日付の矛盾、本人だけの子が共有親の完了や他人の件数に影響しないことを確認する。既存の完了・繰り返し・アーカイブを壊さない。

  4. WBSとガントを表示する

    共有タスクの一覧・文字付き信号・閲覧専用ガントを作る。週を初期表示にし、日に切り替えられるようにする。見た目を試し、複雑なら一覧だけに見直す。

  5. 日報候補と提出後の表示を作る

    対象操作から日報候補を追加し、手動で調整できるようにする。提出済みの内容を保持して下書きと分ける。上司には非共有の名前・件数を出さず、記録時間は「その他」に合算する。

  6. 確認してから共有する

    各段階で自動テストと画面確認を行い、本人・別の担当者・上司で見える範囲を比較する。実データを使わない検証環境で、データ移行・提出後の修正・公開範囲変更も試す。共有環境への公開は別途確認する。

調べる場所：タスク・親子、データの保存、日報、画面と権限、既存テスト。実装位置は着手時に実コードを確認して決めます。

必ず確かめること

  • 他人が非共有タスクの内容・件数を画面や直接のアクセスで取得できない。
  • 非共有の子が共有親の集計・完了を妨げず、本人には未完了として残る。
  • 上司に提出前・再提出前の下書きが見えない。
  • 公開範囲を変更すると、過去の提出分も非共有の名前を隠す。

既存の使い心地も守る

  • 名前だけの追加と、詳しい項目を入れる追加の両方が使える。
  • 未入力の日付を自動設定し、入力済みの日付を勝手に直さない。
  • 自動候補を追加・削除でき、既存の日報入力が消えない。
  • 週・日の切替と、日付・状態を文字でも確認できる。
08 / 未決定

実装前に、まだ確認が必要なこと

決めていないことを勝手に仕様にしないためのメモです。上から順に、必要な時点で相談します。

確認することなぜ必要か
チームの共有環境とログイン方法現在は個人PC内で動くため。既存案のAzureを含め、利用環境・権限・費用を確認。
管理者と案件の参加者の決め方誰が案件を作成し、誰が共有タスクや他人の予定を変更できるかを確定するため。
他人が担当するタスクの非共有化「自分だけ」の所有者と担当者が食い違わないようにするため。
親の信号・予定と実績の集計条件非共有の子を除くことに加え、日付未設定・共有の子が０件・過去時点・完了後の扱いを決めるため。
日報候補に入れる操作の範囲着手・完了以外に、どの更新を候補化するか。取り消しや候補から外した後の扱いも決めるため。
過去の日報と公開範囲を戻した場合非共有から再び共有へ変えたとき、過去の提出分を再表示するかを決めるため。
既存の空欄・繰り返し・アーカイブ新しい日付と公開範囲の初期値を、保存済みデータにどう適用するかを決めるため。
提出済み日報の表示内容親の進捗や日報の備考をどう表示・保存するか。備考に本人が記入した非共有の内容は自動で判別できないため。
ファイル出力や工数集計現時点は画面での確認が優先。Excel出力・案件別工数集計・見積もりは採用未定。

まずは、このたたき台を確認

画面イメージと作業の順番に、認識違いや足りないところがないか確認します。実装は、未決定事項と既存方針の変更を相談してから、小さく進めます。
