# 引き継ぎガイド

このアプリを受け取った人が、最初に読む手順書です。
起動のしかた、直したあとの反映のしかた、困ったときの対処をまとめています。

- アプリの使い方は [README.md](../README.md) を見てください。
- 「なぜこう作っているか」は [設計方針.md](設計方針.md) にあります。機能を変える前に必ず読んでください。

---

## 引き継ぎ後の進め方

1. **読む**: [README.md](../README.md) と `docs` フォルダの文書を読みます。だいたいの仕様と、なぜそう作ったかの経緯が書いてあります。構成は README の図にあります。
2. **使ってみて直す**: まずは ToDo を実際に毎日使います。使いにくいところや細かい修正を、GitHub Copilot と一緒に進めます(「5. Copilot に頼んで直すとき」)。
3. **上司に報告する**: 上司確認画面を作る前に、この時点で一度、上司に報告します。報告で伝えるとよいこと:
   - 実際に使ってみた感想と、直したところ
   - 画面のようす(タスク画面・日報・ミニ表示)
   - 上司確認画面で見られるようにする予定のもの(長時間化・期限超過・相談中と理由。設計方針 4 章)と、見せないもの(工数の集計など。設計方針 5 章)
   - 上司確認画面で、他に見たいものがあるか(ここで要望を聞いておくと、作り直しが減ります)
4. **上司確認画面を作る**: 上司確認画面には全員のデータが要るので、先にログインで本人を見分ける仕組み(複数ユーザー化)を作ります。手順は [次の作業.md](次の作業.md) の段階②・③です。
5. **Azure の Web Apps に載せる**: 手順は [次の作業.md](次の作業.md) の段階④です。載せたら完了です。

## 0. 受け取ったら最初にやること

1. 「1. 初回セットアップ」を行います。
2. テストを実行し、すべて通ることを確かめます(「5. Copilot に頼んで直すとき」のコマンド)。通れば、受け取ったものが正しく動く状態です。
3. `start.bat` で起動し、タスクを1つ追加してみます。
4. 次の文書に目を通します。全部を覚える必要はありません。どこに何が書いてあるかを知っておけば十分です。
   - [README.md](../README.md): 使い方と構成図
   - [設計方針.md](設計方針.md): なぜこう作っているか
   - [次の作業.md](次の作業.md): 次に何をするか
   - [AGENTS.md](../AGENTS.md): Copilot が守る作業ルール(Copilot が自動で読みます)

**データについて**: `data` フォルダには、前の担当者のタスクと日報が入っています。受け取るフォルダには含めない約束です。
`data` が無い状態で起動すると、空のデータベースが自動で作られます。

## 1. 初回セットアップ(最初に 1 回だけ)

フォルダの中に `.venv` というフォルダが無いときだけ行います。

1. Python 3.11 以上が入っているか確認します。PowerShell で次を実行し、`Python 3.11.x` のように表示されれば大丈夫です。

   ```powershell
   python --version
   ```

2. このフォルダを PowerShell で開き、次の 2 行を順に実行します。

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

## 2. 起動と終了

- **起動**: `start.bat` をダブルクリックします。黒いウィンドウが開き、準備ができるとブラウザで ToDo が開きます。
- **使っている間**: 黒いウィンドウは閉じずに、最小化しておきます。
- **終了**: 黒いウィンドウを閉じます。
- **もう一度開きたいとき**: すでに起動していれば、`start.bat` をダブルクリックするとブラウザで開き直すだけで終わります。
- **小さく使う**: ヘッダー右の「ミニ表示」で、今日やるタスクだけの小さな窓が開きます。常に手前に出したいときは、PowerToys が入っていれば Win + Ctrl + T で固定できます。
  小窓の準備ができたら元画面を閉じます。ブラウザが自動で閉じる操作を許可しない場合は、元画面の自動更新を止めて案内するので、そのタブを手動で閉じてください。「全体表示に戻る」では全体画面を再利用または新しく開き、準備ができてから小窓を閉じます。サーバー用の黒いウィンドウは閉じずに残します。

## 3. プログラムを直したあとの反映

プログラムを直しても、動いている ToDo には自動では反映されません。次の順で起動し直します。

1. 黒いウィンドウを閉じる。
2. `start.bat` をダブルクリックする。

黒いウィンドウを閉じ忘れたまま `start.bat` を実行すると、「更新前の古い ToDo が動いています」と表示されます。その場合は古いウィンドウを閉じてから、もう一度実行してください。

## 4. 困ったとき

| 症状 | 対処 |
|---|---|
| 黒いウィンドウに「更新前の古い ToDo が動いています」 | 前に開いた黒いウィンドウを閉じてから、もう一度 `start.bat`。見つからなければ PC を再起動する |
| 黒いウィンドウに「ToDo 以外のプログラムが使っている」 | PC を再起動してから、もう一度 `start.bat` |
| 黒いウィンドウに「.venv が見つかりません」 | 「1. 初回セットアップ」を行う |
| 黒いウィンドウが一瞬で消える | PowerShell でこのフォルダを開き `.\start.bat` と入力して実行すると、エラーの内容が読める。その内容を Copilot に貼って相談する |
| ブラウザに「このサイトにアクセスできません」 | 黒いウィンドウが閉じていないか確認する。閉じていたら `start.bat` で起動し直す |
| 画面の上に赤い帯で「サーバーに接続できません」 | 同上 |
| 画面に「Internal Server Error」 | 黒いウィンドウに出ている英語のエラーをコピーし、Copilot に貼って相談する |
| 直したのに見た目が変わらない | 「3. 直したあとの反映」を行う。それでも変わらなければブラウザで Ctrl + F5 |
| VS Codeで `fastapi` や `pytest` が「見つからない」と出る | Ctrl + Shift + P →「Python: インタープリターを選択」で、このフォルダの `.venv\Scripts\python.exe` を選ぶ。アプリの起動に使うPythonと、VS Codeが確認に使うPythonをそろえる |

## 5. Copilot に頼んで直すとき

- Copilot は [.github/copilot-instructions.md](../.github/copilot-instructions.md) を自動で読み、そこから AI 向けの作業指示 [AGENTS.md](../AGENTS.md) と設計方針を読んで作業します。
- **1 回の依頼は小さく**。「日報画面の備考欄を大きくして」のように、1 つずつ頼みます。
- 直してもらったら、**テストが全部通ったか** を確認します。Copilot が実行しない場合は、自分で次を実行します。最後に `passed` とだけ出て `failed` が無ければ大丈夫です。

  ```powershell
  .\.venv\Scripts\python.exe -m pytest
  ```

- テストが通ったら、「3. 直したあとの反映」で起動し直し、画面で確かめます。
- 方針に関わる変更(画面を増やす、上司に見せる情報を変えるなど)は、先に開発者や上司に相談してください。

## 6. どこに何があるか

| 場所 | 中身 |
|---|---|
| `start.bat` | 起動用。中身は最小限で、実際の起動処理は `app\launcher.py` にある |
| `app\main.py` | 画面の URL と、どの画面を表示するかの組み立て |
| `app\tasks.py` | タスクの作成・更新・進捗・繰り返しなど |
| `app\daily.py` | 「今日やる / 明日以降にやる」の振り分け、アーカイブ、作業時間 |
| `app\reports.py` | 日報(作業時間の集計、下書き保存、提出) |
| `app\blockers.py` | 困りごとフラグ |
| `app\db.py` | データベースの表の定義 |
| `app\templates\` | 画面の HTML |
| `app\static\style.css` | 画面の見た目 |
| `tests\` | 自動テスト |
| `data\todo.db` | **実際のデータ**。消したり上書きしたりしない |
| `app\mcp_server.py`, `app\ai\` | Copilot Chat 連携(一時停止中。今は触らなくてよい) |

## 7. データのバックアップ

データはすべて `data\todo.db` という 1 つのファイルに入っています。
大きな変更を試す前は、黒いウィンドウを閉じてから、このファイルを別の場所にコピーしておきます。
戻したいときは、黒いウィンドウを閉じてから、コピーしておいたファイルで上書きします。
